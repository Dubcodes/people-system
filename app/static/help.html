Start Here

The Short Version

This system is here to answer one race-day question quickly: who is involved, where are they involved, and what should the screen show right now?

You do not need to understand the database to use it. Most people will live in the Viewer. The LOVERACING page is for loading the day's official race data. The admin-style pages are there when something needs tidying, checking, or undoing.

Most race days should become automatic: LOVERACING checks the calendar, matched meetings appear as candidates, and imported data drives the Viewer. The manual controls are there for checking, correcting, and recovery when something needs a human.
If you are running the screenOpen the Viewer, pick or follow a race, and search for people as needed.
If you are loading race dataOpen LOVERACING, preview the meeting, then import when it looks right.
If something looks wrongCheck LOVERACING first, then Race Management. Undo the meeting import if needed.
If a person looks wrongUse Manage People or Image Ingest to improve names, aliases, visibility, and photos.
The useful mental model: LOVERACING is the official source for race-day fields. This app keeps a local working copy so the Viewer can keep running even if the internet, LOVERACING, or an import has a bad moment.
Examples

Screenshots And Demo Clips

These short examples show the main race-day workflows. The videos loop silently like moving screenshots, and you can click one to pause or play it again.

Main Viewer Layout

This is the screen most people will use during a race day. The top row holds the race controls, Auto mode, search, and small utility buttons. The middle area shows the current race or pre-race group, and the lower roster lets you find people by role, region, or photo status. The quick-look panel on the right opens when you select a person.

Operator View

The Operator page follows what the Viewer is doing, so a second screen can stay in step with the main screen. When someone is selected on the Viewer, they appear large on the Operator view. The operator can also click a tile to add an orange highlight, making it easy for both screens to point at the same person without changing the selected race.

Add People To Pre-Race

Use this when someone should appear in the pre-race group even though they are not attached to a specific runner. Select the person from the Viewer, use the quick-look action to add them to pre-race, and they will stay available in that pre-race context for the selected date and track.

Single Image Ingest

Use Image Ingest for one photo at a time. Drop or choose the image, fill the person name and useful metadata, then save it. If the file name already matches a person, the page can suggest that record so you do not have to type everything again.

Bulk Image Ingest

Bulk Ingest is best when you have a folder of named images. Drop the files together, review the suggested person matches, leave only the useful images selected, and either process the checked images now or upload them to the shared Pending Queue. Pending uploads stay unassigned unless you deliberately choose a target region on the row.

Manual Race Ingest

This is the fallback race import method. Copy each race from the source page, paste it into the matching race box, and preview the result before saving. LOVERACING import is preferred for current race days, but manual import is still useful when you are working from older race data or a source the auto-loader does not support.

LOVERACING Auto Loader

This page is where official race-day data is discovered, previewed, imported, audited, and undone. The top area shows automation status and manual preview/import controls. Calendar candidates let you inspect upcoming meetings before import. Import Scope decides which courses can be matched automatically and which region they land in.

Settings Screen

Settings is for display behaviour and race-day convenience tools, not heavy importing or cleanup. Use it to adjust how this screen opens, apply or clear a date override for testing, change theme colours, add manual attendees to pre-race or a race, and check a read-only summary of local imported race days.

Main Viewer

The Screen Most People Will Use

The Viewer is meant to feel simple in the middle of a busy day. Pick a race, search for a person, open quick details, and keep moving. Import and maintenance tools live elsewhere so this screen does not get crowded.

Race selector and Auto Race Mode, in plain terms
  • AUTO: ON means the screen follows the next race for you.
  • AUTO: OFF means you choose the race yourself and the screen stays there.
  • If someone clicks a track, Pre, or a race while auto is on, Auto turns off immediately.
  • Turn AUTO: ON again when you want the viewer to follow the official race times.
Search and people tiles

Use the search box when someone asks for a person quickly. It checks names, aliases, and stable-style text. The small half-filled circle near the Settings button controls whether people without images are shown. That choice is global, so the Viewer and Operator screen stay in step.

Quick-look panel

The quick-look panel is the fast answer panel. It shows the selected person, image, race involvement, notes, and a link to the full record. If LOVERACING supplied silk data, the horse's silk appears beside the horse name. Hover it to see the official colour description.

Pre-race people

Pre-race is manual-led. The system no longer fills this panel with every presenter or staff record, because some people are studio-only or venue-specific. Add the people you expect on track from the Viewer quick-look panel or the Manual Attendees tool in Settings.

Stale data warnings

If an import failed or the data is getting old, the Viewer should keep showing the last good race data and quietly warn you. That is intentional. A stale warning is better than an empty race-day screen.

LOVERACING

Race-Day Auto Loader

This is the control room for official race-day data. Use it when you want to see what the system found, check a meeting before import, or undo a meeting import that was not right.

Tagged courses

The local courses the system is allowed to care about.

Calendar candidates

Meetings the system found on the LOVERACING calendar.

Imported meetings

Meetings already loaded into this app.

Last check

The last time the system looked for meetings.

Automation controls, without the scary bit
  • Auto check calendar at 5:00 AM means the system can look each morning without you pressing anything.
  • Auto import matched meetings means matched meetings can write race data by themselves. When this is on, imported meetings are also refreshed during race day, including a 7:00 AM scratchings check, occasional daytime freshness checks, and the normal pre-race checks.
  • Check Calendar Now looks for meetings now. It does not import unless auto-import is enabled or you click an import action.
  • Force import when unchanged is for the rare case where you want to rewrite data even though the source page looks unchanged.
Manual preview and import
  1. Paste a LOVERACING meeting overview URL.
  2. Choose the target region.
  3. Click Preview and check the meeting, race count, runner count, and warnings.
  4. If it looks right, click Import.
Import Scope: Tagged Racecourses And Regions

This is the list of courses the system is allowed to pull in automatically. A course with Import turned on can be matched from the calendar. LOVERACING match is the name the system looks for. Region is where the meeting should land by default. If the calendar shows an unmatched meeting, use Add Course on that candidate or add the course manually in this section, then run the calendar check again.

Snapshots and audit runs

The audit history is there so we can answer "what happened?" later. Every successful fetch keeps the raw source, a content hash, parser version, timing, warnings, and status. Old failures may stay visible as history, but if a newer run succeeded, those older failures are not current problems.

Trainer name warnings

Some LOVERACING trainer fields use initials, especially partnership names such as G A & D G Rogerson & Clint Isdale. The importer keeps the race data, expands the obvious shared surname where it can, adds an import warning, and marks those records with a small review chip in the Viewer and Manage People. If LOVERACING includes a training location after a comma, such as Peter Coutts, Te Awamutu, the importer treats the comma text as location metadata and keeps the person name as Peter Coutts.

LOVERACING sometimes hides useful race details behind Open/Close sections. The importer is built to read the source and detail pages, not just whatever happens to be visible on screen.
Race Management

Checking What Is Already Loaded

Race Management is not usually the first place to go. Think of it as the inspection bench for race data that has already been imported.

  • Use it to review imported meetings, races, and entries.
  • Use the silk catalog to browse captured silk images and their LOVERACING descriptions.
  • Use LOVERACING for new official race-day imports where possible.
  • If a meeting import is wrong, go back to LOVERACING, undo that meeting's races, then preview and import again.
People And Images

Keeping The Human Side Tidy

Manage People

Manage People is where you clean up the names people actually search for. You can open and read records without unlocking the page. When you try to save, delete, merge, or change linked data, the page asks for the appropriate PIN. If two records are the same person, use Duplicate Cleanup to merge the old record into the one you want to keep. This is useful for married-name changes while preserving the other name as an alias.

Keep roles simple on purpose. If the broadcast says someone is a co-trainer, mark them as Trainer in this database so the race-day filters stay easy to use. Put extra context in Notes instead, such as "CEO of Ellerslie" for a racecourse CEO who is otherwise marked as Staff.

Image Ingest

Image Ingest is for attaching photos to people. A good photo can save a lot of time on race day because the team can recognise someone before reading the details. When you choose a file, the page checks the file name against existing person records. If it finds one clear match, a small suggestion appears beside the file picker. Click it to fill the person fields from that record, or ignore it and enter the details normally.

Bulk Ingest

Bulk Ingest is for a folder-sized batch. You can review local dropped files immediately, or upload them into the shared Pending Queue so someone can process them later. Pending uploads record who uploaded them, but they stay For Unassigned unless you choose a target region on that image row. Processing and saving images needs the Edit PIN. Deleting pending queue items needs the Master PIN. The queue keeps a file hash so the same file is not uploaded twice as an active pending item.

Horses

The Horses page helps you check horse records and the people linked to them. Trainer partnerships from LOVERACING are preserved carefully, because splitting names too aggressively can create bad records.

Settings

Making This Screen Behave

  • Viewer defaults: decide how this browser's viewer opens.
  • Auto Race Mode: chooses whether this screen starts in automatic race-following mode.
  • Race Date Override: helps when you are testing a meeting from another date. Applying it shows a warning and clearing it puts the screen back on the real race day.
  • Theme colors: let you tune the look for a venue, screen, or preference. Quick-click a preset to load it; long-hold a preset to save the current colours after confirmation.
  • Manual attendees: add or remove people from pre-race or a selected race without needing a PIN.
  • Local race info: shows compact read-only recent and upcoming race days for this region.
Most Settings controls are saved in the browser you are using. The global show/hide people-without-images option is shared so Viewer and Operator screens stay in step.
Safety

What Is Safe To Press?

Preview is safe

Preview looks at the data without importing races or changing the live race-day view.

Import writes data

Import updates the local meeting, races, runners, and involvement.

Undo Races is targeted

It removes imported races and entries for that meeting. It does not delete your people database.

Last good data stays

If LOVERACING fails, the Viewer should keep using the last successful import.

PINs protect writes

Viewer quick-adds and manual attendee actions are open for race-day speed. Normal record maintenance asks for the Edit PIN. Deletes, merges, imports, cleanup, recovery, and system maintenance ask for the Master PIN.

PINs are regional

Admin can set Edit and Master PINs for the current app region. Old global PIN overrides may still exist as legacy fallbacks, and environment/default PINs remain available for recovery if regional values are forgotten.

Backups run weekly

The system keeps weekly automatic database backups and rotates the newest four. Manual backups made in Admin stay until someone deletes them.

When an import is wrong, do not start deleting people or horses. Undo the meeting's races, then preview and import again.
Troubleshooting

When Something Feels Off

I expected a meeting, but it is not showing
  1. Open LOVERACING and click Check Calendar Now.
  2. Check whether the course is listed in Import Scope and has Import turned on.
  3. Confirm the LOVERACING match name matches the venue wording from the calendar.
  4. If discovery still misses it, paste the meeting URL into Manual Preview and import it manually.
I can see old failed import runs

That is usually just history. If a newer successful run appears above them, the current importer is working. Turn on failed history only when you need to inspect old errors.

The Viewer is on the wrong race
  1. Check whether Auto Race Mode is on or off.
  2. Check the imported race start times on Race Management or LOVERACING preview.
  3. Clear any Race Date Override in Settings unless you are testing another date.
  4. Turn Auto back on if the viewer was manually moved to another race.
A runner, jockey, or trainer looks wrong
  1. Preview the meeting again on the LOVERACING page.
  2. Check whether the source page changed after the last import.
  3. If auto import is on, the system should refresh current-day meetings from 7:00 AM and then through the day. Use manual import if you need to pull the latest page immediately.
  4. Use force import only if the source appears unchanged but you still need to rewrite the local data.
  5. If the meeting was imported incorrectly, Undo Races and import again.
Reference

Words The System Uses

Meeting

A race-day event at a venue, such as Matamata RC @ Matamata.

Race

One scheduled race within a meeting, with a race number, name, start time, conditions, and distance.

Runner

A horse entered in a race. It may have a number, barrier, rating, weight, jockey, trainer, odds, and status.

Scratched

A runner removed from the race. Scratched runners may not have jockeys or odds.

Ballot

A runner marked with a ballot suffix such as B1 or B2.

Region

The local app region where imported data belongs, such as Northern, Central, Christchurch, or Dunedin.

Snapshot

The saved raw LOVERACING HTML used for an import or preview.

Content hash

A fingerprint of the source page. If the hash has not changed, the importer can skip unnecessary rewrites.

Notes

Free-text context that should not become a role or filter, such as CEO titles, broadcast wording, or why a person was marked a certain way.
